# Measurement Instrument Control — Windows / АКИП-2205

Приложение на C: cimgui + Dear ImGui, GLFW/OpenGL3, Win32 COM-порт.
Реализован обмен из комплектного
`DMM 2205/DMMVIEW_G(2.2)/DMMVIEW_G Communication Protocol(0.0).pdf`
(также сверено с его CHM-версией).
В начале этого документа прямо заявлено соответствие SCPI. Реализовано
именно документированное подмножество команд АКИП-2205; одинаковое название
SCPI не означает, что прибор принимает любые команды другого инструмента.

Можно выбрать COM-порт, установить связь, запросить одно измерение,
запустить/остановить периодическое чтение, выполнить документированный
сброс RST, увидеть график и сохранить CSV.
Показания поступают только от подключённого прибора. Режим и предел
измерения меняются кнопками/переключателем на самом мультиметре.

Это график последовательных показаний мультиметра, а не осциллограмма
быстрого сигнала. Руководство указывает до 3 обновлений основного индикатора
в секунду; это не гарантия частоты USB-ответов. Запросы приложения идут
последовательно с заданным интервалом 0,4–5 секунд между запросами,
при условии получения предыдущего ответа. По умолчанию — 400 мс:
это интервал, указанный в справке DMMVIEW_G для настройки 00:00:00.
Если ответ идёт дольше интервала, частота автоматически уменьшается;
пропущенные запросы не догоняются пачкой.

## Подготовить программу на Windows

1. Установить **Visual Studio 2022 / Build Tools 2022**, компонент
   **Desktop development with C++**, MSVC и Windows SDK.
2. Установить **CMake >= 3.21** и Git for Windows. CMake должен быть в PATH;
   его также можно получить с компонентами Visual Studio.
3. Перенести этот репозиторий с внесёнными изменениями на Windows.
   Нужны корневые `cimgui.cpp`, `cimgui.h`, `cimconfig.h`, `cimgui_impl.h`,
   каталог `imgui`, каталог `measurement_app`.
4. Открыть PowerShell в корне репозитория и выполнить:

```powershell
git submodule update --init --recursive
cmake -S measurement_app -B build/measurement-windows -G "Visual Studio 17 2022" -A x64 -DBUILD_TESTING=ON
cmake --build build/measurement-windows --config Release --parallel
ctest --test-dir build/measurement-windows -C Release --output-on-failure
.\build\measurement-windows\Release\measurement_control.exe
```

Каждая команда должна завершиться успешно перед выполнением следующей.
Можно вместо этих команд выполнить скрипт сборки:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\measurement_app\build-windows.ps1
.\build\measurement-windows\Release\measurement_control.exe
```

Скрипт не устанавливает программы и не запускает GUI. При отсутствии
Dear ImGui сначала отдельно выполнить команду инициализации подмодуля выше.

GLFW 3.4 скачивается автоматически, если CMake не нашёл установленный GLFW.
Для сборки без сети сначала подготовить исходники GLFW 3.4 и добавить к
команде конфигурации:
`-DFETCHCONTENT_SOURCE_DIR_GLFW=C:/deps/glfw-3.4`.
Для рекомендованной сборки MSVC с автоматически собранным GLFW библиотеки
и CRT линкуются статически; переносится `measurement_control.exe`.
Если использован сторонний динамический GLFW, потребуется его DLL рядом
с exe и совместимая конфигурация CRT. Графический драйвер должен
поддерживать OpenGL 3.2 Core; одного базового Microsoft GDI-драйвера мало.

В `.github/workflows/measurement-windows.yml` добавлена сборка Windows x64
и запуск тестов парсера. После отправки изменений в GitHub workflow
`Measurement Control Windows` публикует артефакт
`measurement-control-windows-x64` с exe и этой инструкцией. Его можно
распаковать на компьютере с прибором без установки инструментов разработки.
Workflow подготовлен, но в этой сессии не запускался; изменения не отправлены
в удалённый репозиторий.

## Подключить и проверить настоящий мультиметр

1. **Сначала проверить сам прибор.** Включить АКИП-2205. Для первого
   измерения выбрать DCV, чёрный щуп подключить к COM, красный к входу
   напряжения V/Ohm. Проверить обычную батарейку 1,5 В и запомнить показание.
   Для этой проверки не использовать сеть 230 В и не вставлять красный
   щуп во вход измерения тока.
2. Подключить штатный интерфейсный USB-кабель из комплекта к прибору и ПК.
   Выполнить требования руководства прибора по подключению ПК к заземлению
   (раздел Wired Communication в `Product User Manual.pdf`, стр. 30).
   Для проводной версии Pair и включение wireless не требуются: эти
   инструкции относятся к беспроводной модификации. Приложение не меняет
   системные настройки прибора.
3. Открыть **Диспетчер устройств → Порты (COM и LPT)**. Определить новый порт
   подключением кабеля, например `COM7`. Ожидаемое устройство —
   **Silicon Labs CP210x USB to UART Bridge / CP210x USB to UART Bridge
   Controller (COM7)**: это прямо указано в новых инструкциях драйвера и
   справке DMMVIEW_G. Если порта нет, отключить кабель, установить драйвер
   **CP210x VCP** для своей версии Windows и подключить снова.
   Для Windows 10/11 брать пакет с
   [официальной страницы Silicon Labs](https://www.silabs.com/software-and-tools/usb-to-uart-bridge-vcp-drivers),
   выбрав поддерживаемую ОС/архитектуру. Комплектная инструкция описывает
   Windows 2000/XP и старый `CP210x_VCP_Win2K_XP.exe`; переносить её
   установочные шаги буквально на Windows 10/11 не следует.
   В предоставленной папке этого установщика нет: AN144SW содержит
   материалы настройки USB-идентификаторов, а не VCP-драйвер.
   Дополнительная проверка списка портов в PowerShell:

   ```powershell
   [System.IO.Ports.SerialPort]::GetPortNames()
   Get-CimInstance Win32_SerialPort | Select-Object DeviceID, Name, PNPDeviceID
   ```

   Этот транспорт соответствует комплектной документации:
   **CP210x → виртуальный COM-порт**. Если вместо него обнаружилось другое
   устройство, сначала сверить кабель, модель и аппаратный идентификатор.
   Наличие CP210x само по себе не доказывает, что это именно мультиметр:
   выбирать порт подключённого АКИП-2205, а не другого USB–UART адаптера.
4. При наличии штатной программы **DMMVIEW_G** проверить, что она получает
   показания, затем **полностью закрыть её**. Закрыть также терминал и другие
   программы, использующие этот COM-порт: приложение открывает порт эксклюзивно.
5. Запустить `measurement_control.exe`. Нажать **Refresh ports**, выбрать
   именно обнаруженный порт с названием CP210x (приложение отображает
   системное название рядом с COM) или ввести `COM7` в поле **Port**. Оставить
   **CRLF (default)** и нажать **Connect**.
6. Успешная связь: статус **Online: ACK received** и сообщение **RX ACK** в
   журнале. Статус «Port open» сам по себе ещё не подтверждает ответ прибора.
   ACK подтверждает обмен DMMVIEW_G, но не идентифицирует модель/серийный
   номер: команды идентификации в приложенном протоколе нет.
7. Нажать **Read once**. Должны появиться режим DC voltage, значение и V;
   счётчик Measurements должен увеличиться. Сопоставить число и знак с
   экраном мультиметра. Только совпадение режима, единицы и показания
   подтверждает правильность декодирования на вашей прошивке.
8. Нажать **Start acquisition**. График должен заполняться реальными
   показаниями. Можно измерить другую низковольтную батарейку и сравнить
   изменение с экраном прибора. Нажать **Stop acquisition**: новые запросы
   прекращаются; уже отправленный запрос может дать один последний ответ.
9. Для взаимодействия переключить режим или предел **на приборе** и
   снова запросить показание. Программа показывает полученный код режима;
   при смене режима очищает график, чтобы не смешивать разные величины.
   Удалённое переключение функций и стирание памяти не реализованы:
   в предоставленном PDF команд переключения функций нет.
10. Нажать **Export CSV**, задав имя нового файла в доступной для записи
    папке. Например `C:\Users\Public\measurement-01.csv`. Существующий файл
    не перезаписывается. Нажать **Stop acquisition**, **Disconnect**,
    закрыть окно и **только после этого отсоединить USB-кабель**:
    такой порядок указан в Q & A справки DMMVIEW_G.

Pair(2.0) и шаги Scan/Paired используются для беспроводного адаптера,
не для нашего проводного АКИП-2205. `CP210xSetIDs` из документа о нескольких
приборах предназначен для изменения USB-серийных номеров при их совпадении.
Для первого подключения одного мультиметра он не нужен; приложение
не перепрограммирует адаптер и его идентификаторы.

## Как работает прибор и пример команды на C

АКИП-2205 — измеритель: его измерительные входы подключаются к исследуемой
цепи, режим и диапазон выбираются на самом приборе, измеренное значение
показывается на дисплее. USB-интерфейс CP210x переносит команды и ответы
через COM-порт. Это не источник питания с задаваемым пользователем выходным
напряжением. Например, `SetVoltage 1 15.3` не перечислена среди команд
АКИП-2205; её нельзя отправлять ему как будто она документирована.
Для установки напряжения на блоке питания понадобятся отдельный модуль
и команды именно этого блока питания.

Архитектура задания реализуется напрямую:

```text
GUI: Reset instrument → подтверждение Send RST
    → akip_device_reset()
    → akip_reset_command() возвращает "#RST\r\n"
    → Win32 WriteFile передаёт 6 байт в выбранный COM
    → прибор отвечает ACK либо NAK
    → GUI показывает результат и выполняет повторный ONL
```

Функция-пример в `akip_protocol.c`:

```c
size_t akip_reset_command(bool cr_only, char *out, size_t capacity);
```

Использование:

```c
char command[8];
size_t length = akip_reset_command(false, command, sizeof(command));
/* command = "#RST\r\n", length = 6.
 * Передавать нужно length байт; завершающий NUL C-строки не отправляется.
 * length == 0 означает неверный/слишком маленький выходной буфер. */
```

Это чистая функция формирования строки. `akip_device_reset()` отвечает
за проверку состояния, отправку этой строки и дальнейшую обработку ответа.
Вместо логического флага «online или read» общий конструктор команд теперь
принимает `AkipCommand`: ONLINE, READ или RESET. Такой слой можно расширять
функциями с аргументами, когда для нужного прибора есть документированный
синтаксис, единицы и допустимые значения этих аргументов.

**Проверить действие на настоящем приборе:**

1. Собрать программу на Windows, подключить кабель, найти CP210x COM,
   выполнить Connect и Read once по алгоритму выше.
2. Сохранить нужный CSV, остановить опрос и дождаться состояния request: idle.
3. Для первого опыта отсоединить щупы от исследуемой цепи. Оставить прибор
   включённым и USB подключённым, чтобы наблюдать его дисплей.
4. Нажать **Reset instrument**, прочитать пояснение и нажать **Send RST**.
   Команда отправляется только по этому действию, автоматически при
   подключении или ошибках сброс не выполняется.
5. В журнале проверить **TX RST**, hex `23 52 53 54 0D 0A`, затем **RX RST ACK**.
   Согласно протоколу, стр. 4, команда выполняет reset / эквивалент включения
   питания. Наблюдать соответствующее поведение самого мультиметра.
   Конкретная последовательность индикации при запуске в протоколе не описана.
   Очистка графика в программе не считается подтверждением физического сброса.
6. После ACK приложение выдерживает 1 секунду и отправляет ONL повторно.
   Эта пауза — выбранная настройка приложения, не гарантированное время
   загрузки прибора. Дождаться Online, затем повторить Read once.
   Сбор автоматически не возобновляется. Если прибор загружается дольше
   или прерывает порт при сбросе, дождаться его готовности, выполнить Connect
   вручную; при потере USB — полный перезапуск по Q & A.
7. При NAK/тайм-ауте не считать действие выполненным. Сохранить
   **Copy diagnostics** и проверить полученные пакеты/прошивку.

Код соответствует команде из предоставленной документации; реальное
поведение RST и индикацию обязательно проверить на целевом приборе.

## Если не работает

| Симптом | Что проверить |
| --- | --- |
| CP210x COM-порта нет | Штатный кабель, установка CP210x VCP для вашей ОС, ошибки в Диспетчере устройств |
| Windows error 2 | Неверный/исчезнувший номер COM |
| Windows error 5 | Порт занят DMMVIEW_G/терминалом либо нет доступа |
| ONL timeout, RX bytes = 0 | Питание, нужный COM, кабель, режим передачи; сначала проверка штатным ПО |
| ONL timeout при исправной работе штатного ПО | PDF в общей части указывает CRLF, а примеры — CR: выбрать CR (compatibility) и подключиться заново |
| RX bytes растёт, но нет измерений | Сравнить реальный пакет с приложенным протоколом; Copy diagnostics сохраняет журнал и последний RX в буфер обмена |
| RX NAK | Выйти на приборе из просмотра сохранённых записей/памяти в обычный режим измерения |
| OL / overrange | Прибор прислал FFFFFFF: выбрать подходящий предел, сравнить с его экраном |
| Нет окна / GLFW error | Установить драйвер GPU с поддержкой OpenGL 3.2; проверить запуск на физическом ПК |
| CSV creation failed | Доступ к папке, существующее имя файла; задать новое имя |
| Связь не возвращается после случайного извлечения кабеля | По Q & A: закрыть программу, переподключить кабель, запустить программу заново и выбрать актуальный COM |

Тайм-аут ответа — 2 секунды, для RST — 5 секунд.
При тайм-ауте или ошибке COM-порт закрывается:
после устранения причины нажать Connect снова. Если причиной был случайный
обрыв USB, выполнить полный перезапуск по алгоритму из Q & A выше.
Последний ответ после остановки/отключения сохраняется с указанием возраста
и пометкой retained reading, чтобы не выглядеть свежим измерением.

## Формат и границы реализации

- 9600, 8 бит, без чётности, 1 стоп-бит, без управления потоком.
- Отправляется `#ONL\r\n`, затем `#RD?\r\n`; по явному действию пользователя
  отправляется `#RST\r\n`. В режиме CR — без LF.
  Символы `<`/`>` в PDF являются обозначениями и не отправляются.
- Пример TX ONL в hex: `23 4F 4E 4C 0D 0A`.
- ACK по приложению 1: `23 06 00 0D 0A`, NAK: `23 15 00 0D 0A`.
  Это бинарные коды, поэтому ответы не обрабатываются как C-строка.
- RD содержит 26 байт: код функции (2), затем три группы «диапазон (1)
  и значение (7)». Принимаются разорванные чтениями и последовательно
  пришедшие кадры. Для вывода используется первый канал; остальные доступны
  в сыром RX. CRC в этом протоколе не описана.
- Число для графика/CSV приводится к базовой единице: mV → V,
  uA/mA → A, kOhm/MOhm → Ohm, kHz/MHz → Hz, nF/uF → F.
  Переход диапазона с той же величиной не меняет единицу графика.
- FFFFFFF рисуется разрывом, а не нулём. При паузе между сеансами график
  также не соединяет пропущенное время выдуманной линией.
- PDF неоднозначно задаёт признак C/F и диапазоны ёмкости 5–7.
  Эти значения отображаются с предупреждением без числовой точки/угаданной
  единицы. Для их поддержки нужны фактические пакеты, сверенные с экраном.
- Сохраняются до 1024 записей текущей серии, включая отметки разрывов.
  Ось X — время в секундах
  относительно первого сохранённого ответа. CSV содержит время от запуска
  приложения, значение в базовой единице, единицу, valid и код функции.
  Для недостоверного/нечислового значения и отметки паузы поле value_si пустое.
- Запросы имеют не более одного ожидаемого ответа. После тайм-аута сессия
  закрывается, чтобы поздний ответ не принять за новое измерение.
- Команды `*IDN?`, `MEAS:VOLT?`, изменение режима, запись/стирание памяти
  и управление блоком питания не отправляются.

## Файлы и проверки

- `main.c` — окно, события, вызов опроса и освобождение ресурсов.
- `akip_device.c` — реальный Win32 COM-обмен, состояния, история, CSV.
- `akip_protocol.c` — команды, пример `akip_reset_command()`, сборка кадров
  и разбор полученных измерений.
- `akip_device.h` — состояние прибора и значения, передаваемые интерфейсу.
- `instrument_ui.c` — интерфейс и график без дополнительной plotting-библиотеки.
- `tests/protocol_test.c` — тесты разорванных/повреждённых кадров, бинарных
  ACK/NAK, единиц, переполнения, синхронизации. Искусственные байты есть
  только в тестах, в приложение они не попадают.

Дополнительная проверка окна **на Windows** без подключения:

```powershell
.\build\measurement-windows\Release\measurement_control.exe --smoke-test
```

Она рисует 120 кадров, запрашивает изменение размера и закрывает окно.
Порт без нажатия Connect не открывается. Полную аппаратную проверку
проводить по алгоритму выше: ответ, сравнение показаний, остановка,
закрытие программы, отключение кабеля и повторный запуск после подключения.
